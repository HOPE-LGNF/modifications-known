# 游戏日志

> 面向用户与维护者。最后核对：`feat/log-viewer`，2026-11-19。

启动器的「游戏日志」页用于在本机查看 BepInEx 与 Unity 写出的日志，帮助判断模组加载失败、补丁冲突或游戏崩溃。它只读、只看本机、不上传。

## 入口与来源

顶部导航「日志」，页面标题「游戏日志」，位于「存档管理」与「启动器外观」之间。顶部「日志文件」下拉提供四类来源：

首次进入默认选择「BepInEx 日志」，对应当前选中的实例；本次会话里手动切到 Unity 或手动文件后，离页再回来会保留该选择，不强制切回。选择不会被持久化到设置，重启后回到默认。BepInEx 日志文件缺失时显示「尚未找到日志」，不会静默切换到 Unity。

| 来源 | 路径 | 说明 |
|---|---|---|
| BepInEx 日志 | `<实例目录>\BepInEx\LogOutput.log` | 绑定当前选中的实例；没有实例时不可读取 |
| Unity 日志 · 当前游戏数据目录 | `%USERPROFILE%\AppData\LocalLow\Orsoniks\CasualtiesUnknown\Player.log` | 正式版与试玩版共用该目录 |
| Unity 日志 · 上一次运行 | 同目录 `Player-prev.log` | Unity 在下次启动时轮换 |
| 手动文件 | 用户选择的 `*.log` / `*.txt` | 从「更多 ▾ → 选择其他日志文件…」载入，仅本次会话有效 |

Unity 来源的归属文案固定为：

```
Unity 日志 · 当前游戏数据目录
显示该目录中已有的日志，不能确认生成时使用的实例。
```

原因：MK 的存档隔离会把 `%LocalLow%\Orsoniks\CasualtiesUnknown` 链接到当前存档组目录，因此同一个 LocalLow 路径在不同时间可能指向不同组的文件；日志也可能随存档组被导入、复制或迁移。所以目录只说明文件此刻在哪，不能反推它由哪个实例或哪个组生成。页面不展示组名、不解析存档组目录结构。

## 读取规则

- 每次读取只打开一次文件句柄，长度、定位、探测与读取都基于该句柄；读取途中不按路径重开。
- 只读打开，`FileShare.ReadWrite | Delete`，游戏正在写日志时也能读，不阻塞游戏。
- 只取文件尾部：最多 2 MiB；窗口可能在 UTF-8 多字节字符或 UTF-16 码元中间切开，读取器会先对齐再解码，切点落在行中时丢弃残行，不伪造前缀。
- 编码由同一个句柄在文件头探测：UTF-8（含 BOM）、UTF-16 LE/BE（BOM）。尾窗本身不含 BOM 时也能按文件头识别，不会退化成 UTF-8。无 BOM 按 UTF-8，坏字节替换为 `�` 并给出提示，不猜 ANSI。
- 最多保留最新 5000 条；单条超过 32 KiB 会保留尾部内容并标记为不完整。
- 截断与解码状态按原因报告：尾部窗口、条目数上限、单条长度上限、坏字节替换各有独立提示，不再统一说“只读取了最近 2 MiB”。
- 读取预算可测量：读取器报告本次实际读出的字节数，包含固定的编码探测与对齐开销（探测 4 字节 + UTF-8 回看至多 3 字节，不计入 2 MiB 窗口）；测试据此断言没有全量读取。
- 条目身份使用源文件内的绝对字节偏移，窗口随文件增长而移动时，同一条仍在快照中的日志保持同一身份。
- 日志轮换或截短时按新文件重新解析，不把新内容接到旧缓冲后面。
- 切换游戏实例时，BepInEx 来源立即丢弃旧快照并重新读取，迟到的旧结果不会回写；Unity 与手动文件不跟随实例，内容保持不变。

## 解析与级别

- BepInEx：识别 `[Level: Source] message` 前缀；`Debug / Info / Warning / Error / Fatal` 映射为对应级别，`Message`（BepInEx 自己的横幅级别）按 INFO 处理并保留原始级别文本；其它前缀保留原文但级别为 UNKNOWN。
- 续行（缩进堆栈）归属上一条，不会把每个 stack frame 计成一次独立异常。
- Unity：没有级别前缀，全部为 UNKNOWN；缩进行归入上一条。
- 被截断的头部即使“看起来像合法前缀”也降级为 UNKNOWN，避免误报级别。
- 没有时间戳就不生成“发生时间”。

筛选三档：全部（含 UNKNOWN）、警告与错误、仅错误。搜索是大小写不敏感的字面子串，不支持正则；范围可选「全部内容」「日志来源」「日志内容」，默认全部内容。输入防抖约 200ms。「日志来源」指日志行方括号中的来源字段（例如 BepInEx、Together），不等于已安装插件名；「日志内容」指该条的正文与堆栈。

## 列表与表头

列表上方是固定表头「级别 / 日志来源 / 日志内容」，与数据行共用相同的列宽、间距和水平内边距；表头不随列表滚动，右侧留出滚动条占位以免错位。级别列按内容自适应宽度，完整显示 INFO、WARN、ERROR、UNKNOWN；来源与内容过长时省略，完整内容在右侧详情查看。

## 更多菜单

标题栏右侧「更多 ▾」提供三个动作，互不混用：

| 菜单项 | 含义 |
|---|---|
| 用默认程序打开当前日志 | 用系统关联程序打开当前正在查看的那份文件 |
| 打开所在文件夹 | 用资源管理器定位当前日志所在目录 |
| 选择其他日志文件… | 文件选择器，把选中的日志载入本页面只读查看；取消则保持当前来源与快照不变 |

目标文件或文件夹不存在时只提示，不创建、不回退到猜测路径。

## 复制与隐私

- 「复制列表日志（N 条）」复制左侧当前显示的全部条目（含未滚动到的行），与是否选中某条无关；按钮文字里的 N 是当前匹配数。
- 「复制此条日志」只复制右侧选中的那一条完整条目（含堆栈）。
- 复制不弹确认框：它只写入本机剪贴板，不上传；页面顶部保留隐私提示，复制后给出简短状态反馈。分享前检查日志中的敏感信息。
- 复制内容首行是 `== <来源> · 读取于 yyyy-MM-dd HH:mm:ss zzz ==`。这是快照读取时间，不是日志发生时间。
- 快照被截断时，复制内容会附带“不是完整日志”的声明。
- 日志正文、搜索词都不会写入 MK 自己的日志；不上传、不自动脱敏、不改原文件。

## 状态与失败

| 状态 | 表现 |
|---|---|
| 尚未找到日志 | 显示「尚未找到日志。游戏运行后可能生成日志，也可以手动打开其他日志文件。」不报红、不建文件、不去其它位置找替代 |
| 空文件 | 「日志为空。」不算错误 |
| 读取失败（换源） | 显示错误原因，不保留其它来源的内容 |
| 刷新失败（同源） | 保留上一次快照，标注失败和原读取时间，不冒充最新 |
| 搜索无匹配 | 列表为空并提示「没有匹配的日志。」，不等于日志为空 |
| 切换来源 | 立即清空旧来源的行、选中、详情、时间戳与截断/解码提示，新来源读取完成前不能复制；读取失败也不留旧时间戳 |
| 切换实例 | BepInEx 来源清空并立即重读；Unity、手动文件保持不变 |
| 同源刷新 | 保留旧快照并显示「正在刷新，显示上次结果…」；失败时显示失败原因与旧快照时间 |
| 离页再回来 | 已有快照（含 Missing/Empty）时不重新读盘；首次进入、显式刷新、切换来源、实例变化才读取 |
| 没有实例且停在 BepInEx | 提示「请选择一个游戏实例，或切换到 Unity 日志 / 选择其他日志文件。」 |
| 截断/编码替换 | 常驻简短提示，按原因措辞，不弹 toast |

## 已知限制

- 不自动滚动到底，也没有“跟随模式”；同源刷新只保证按条目身份保留选中项，**滚动位置不保证保留**。
- 不渲染 HTML/XAML，不激活 URL，不执行路径或命令。
- 没有时间戳、级别、来源的格式一律保留为 UNKNOWN。
- 页面绑定只有视图模型测试；上游缺少 App.Tests，真实 View 的自动化 UI 测试仍是缺口，需人工验收。
